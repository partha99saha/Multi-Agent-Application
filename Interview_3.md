# LLM Engineering Interview Questions & Answers (Part 3)

# 31. Model Routing

## What is Model Routing?

Model Routing dynamically selects the most appropriate model based on task complexity, latency requirements, or cost constraints.

## Why is it needed?

* Cost optimization
* Latency optimization
* Reliability
* Fallback mechanisms
* Multi-provider support

## Common Routing Strategies

### Cost-Based Routing

```text
Simple Query → Small Model
Complex Query → Large Model
```

### Latency-Based Routing

```text
Fast Response Needed → Small Model
High Quality Needed → Large Model
```

### Task-Based Routing

```text
Coding → GPT-4
Reasoning → Claude
Translation → Gemini
```

## Architecture Flow

```text
User Query
      ↓
Model Router
 ┌────┼────┐
 ↓    ↓    ↓
GPT  Claude Gemini
 ↓
Best Response
```

## Libraries

* LangChain RouterChain
* LangGraph
* LiteLLM
* OpenRouter

## Interview Question

### Q: Why use Model Routing?

**Answer:**

Model routing reduces operational costs and latency by directing simple tasks to smaller models and complex tasks to stronger models.

# 32. Caching Systems

## What is Caching?

Caching prevents repeated LLM executions for identical or similar requests.

## Types of Cache

### Prompt Cache

Stores exact prompt-response pairs.

### Semantic Cache

Stores embeddings and retrieves semantically similar responses.

### Retrieval Cache

Stores retrieved document chunks.

### Embedding Cache

Stores generated embeddings.

## Architecture Flow

```text
User Query
      ↓
Cache Check
      ↓
Hit? ── Yes ──► Return Response
      ↓ No
LLM
      ↓
Store Cache
      ↓
Response
```

## Libraries

* Redis
* GPTCache
* LangChain Cache
* Upstash Redis

## Interview Question

### Q: Prompt Cache vs Semantic Cache?

**Answer:**

Prompt cache requires exact prompt matches.

Semantic cache uses embedding similarity and can match semantically related queries.

# 33. Streaming Architecture

## What is Streaming?

Streaming delivers tokens as they are generated rather than waiting for the complete response.

## Benefits

* Better User Experience
* Reduced Perceived Latency
* Real-Time Interaction

## Architecture Flow

```text
User
 ↓
LLM
 ↓
Token Stream
 ↓
Frontend
 ↓
Real-Time Response
```

## Streaming Technologies

### Server-Sent Events (SSE)

One-way communication from server to client.

### WebSockets

Bi-directional communication.

### HTTP Chunked Transfer

Stream response chunks incrementally.

## Libraries

* FastAPI StreamingResponse
* LangChain Streaming
* LangGraph Streaming
* OpenAI Streaming APIs

## Interview Question

### Q: Why stream responses?

**Answer:**

Streaming significantly improves user experience by reducing perceived waiting time.

# 34. Guardrails & Validation

## What are Guardrails?

Guardrails enforce safety, structure, and compliance on LLM inputs and outputs.

## Types

### Input Guardrails

Validate incoming prompts.

### Output Guardrails

Validate generated responses.

### Schema Validation

Ensure JSON structure correctness.

### Security Validation

Detect prompt injection and malicious requests.

## Architecture Flow

```text
User Input
      ↓
Input Validation
      ↓
LLM
      ↓
Output Validation
      ↓
Safe Response
```

## Libraries

* Guardrails AI
* NeMo Guardrails
* Pydantic
* Rebuff

## Interview Question

### Q: Why are Guardrails important?

**Answer:**

They reduce hallucinations, enforce structured outputs, prevent prompt injection, and improve production reliability.

# 35. Knowledge Graph RAG (GraphRAG)

## What is GraphRAG?

GraphRAG augments traditional RAG with knowledge graphs to retrieve relationships between entities.

## Traditional RAG

```text
Query
 ↓
Chunk Retrieval
 ↓
LLM
```

## GraphRAG

```text
Query
 ↓
Entity Retrieval
 ↓
Relationship Traversal
 ↓
LLM
```

## Architecture Flow

```text
Documents
      ↓
Entity Extraction
      ↓
Knowledge Graph
      ↓
Graph Retrieval
      ↓
LLM
      ↓
Response
```

## Libraries

* Neo4j
* LangChain
* LlamaIndex
* NetworkX

## Interview Question

### Q: GraphRAG vs Traditional RAG?

**Answer:**

Traditional RAG retrieves chunks.

GraphRAG retrieves entities and their relationships, providing better reasoning for interconnected information.

# 37. Semantic Search

## What is Semantic Search?

Semantic Search retrieves information based on meaning rather than exact keyword matching.

## Keyword Search

```text
Query:
Cloud Storage

Matches:
Cloud Storage
```

## Semantic Search

```text
Query:
Cloud Storage

Can Retrieve:
Amazon S3
Azure Blob Storage
Google Cloud Storage
```

## Architecture Flow

```text
Query
 ↓
Embedding Model
 ↓
Vector
 ↓
Vector Search
 ↓
Top Similar Documents
```

## Retrieval Process

```text
Document
 ↓
Embedding Model
 ↓
Vector Database
 ↓
Similarity Search
 ↓
Retrieved Chunks
```

## Similarity Metrics

### Cosine Similarity

Most common for embeddings.

### Dot Product

Used by several vector databases.

### Euclidean Distance

Measures geometric distance.

## Libraries

* SentenceTransformers
* OpenAI Embeddings
* BGE
* E5

## Vector Databases

* Qdrant
* Pinecone
* Weaviate
* Milvus

## Interview Question

### Q: Semantic Search vs Keyword Search?

**Answer:**

Keyword search relies on exact term matching.

Semantic search uses embeddings to retrieve results based on meaning and context.

# 38. Query Transformation / Query Rewriting

## What is Query Rewriting?

Query rewriting improves retrieval quality before retrieval begins.

## Techniques

### Query Expansion

Add related terms.

### Multi-Query Retrieval

Generate multiple search queries.

### HyDE

Generate hypothetical answers before retrieval.

### Step-Back Prompting

Generate broader context before retrieval.

## Architecture Flow

```text
User Query
      ↓
Query Rewriter
      ↓
Optimized Query
      ↓
Retriever
      ↓
LLM
```

## Libraries

* LangChain
* LlamaIndex
* DSPy

## Interview Question

### Q: Why rewrite queries?

**Answer:**

Query rewriting improves retrieval accuracy and increases the likelihood of finding relevant documents.
